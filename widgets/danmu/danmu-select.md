# 弹幕优选

## 接口

组件保留 Forward 弹幕约定的三个模块：

- `searchDanmu`：搜索作品并生成带多源 ID 映射的路由。
- `getDetail`：获取选集，严格使用每个来源自己的 `animeId`。
- `getComments`：获取弹幕，严格使用每个来源自己的 `episodeId`。

## 默认调度

1. Alpha 与炊烟属于 `fast` 层，并发请求。
2. 搜索与自动匹配先比较媒体匹配置信度，不按完成时间决定结果。
3. `quality` 模式等待快速层全部返回或耗尽 `fastTimeout`，再比较弹幕质量，避免完成顺序压过质量。
4. 质量判断先执行繁简转换、用户关键词屏蔽和去重。快速层无准确候选，或处理后的弹幕质量低于 `minQuality` 时，才请求 `deep` 层的 Lily。
5. Lily 没有对应的来源 ID 映射时不会拿其他来源的 ID 试探，避免跨库串片。

默认三个地址槽可以替换，也支持在一个地址槽中按行填写多个来源：

```text
来源名称,https://example.com/token
另一个来源，https://example.net/token
```

未知自定义地址默认归入快速层。内置 Lily 地址会被识别为深度层。

## 质量分

质量分是本地启发式指标，不读取或上传弹幕正文到 AI。当前信号包括：

- 可解析且未被用户关键词屏蔽的弹幕比例；
- 去重后的内容比例；
- “签到”“前排”“哈哈哈”“666”等低价值短内容比例；
- 弹幕在播放时间轴上的覆盖与跨度；
- 对弹幕总量做对数饱和，避免单纯以数量取胜；
- 来源画像仅占很小的平分权重。

它用于在已有结果中选择更合适的一组，不代表对弹幕内容真实性或主观好坏的绝对判断。

## 兼容策略

- `quality`：推荐，快速层动态质量优选，必要时使用深度层。
- `fallback`：按路由中的来源顺序做小幅 hedge，兼容传统主备行为。
- `merge`：合并已映射的快速层结果并确定性去重，不常态合并 Lily。

## 超时

- `fastTimeout` 默认 `3500 ms`。
- `requestTimeout` 默认 `25000 ms`，涵盖请求、深度回退和可选繁简转换。
- `graceMs` 默认 `650 ms`，用于完全确定的匹配、详情与兼容策略的同层收集宽限；动态质量模式以 `fastTimeout` 为完整比较上限。

所有路径都共享单次调用总截止时间。超时、限流与服务失败不会被当成永久“无弹幕”写入缓存。
